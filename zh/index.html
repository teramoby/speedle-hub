Speedle Engine

适合在自己的基础设施上运行授权的团队。

用 Go 编写的授权引擎，支持 RBAC 与 ABAC。它评估 SPDL 策略，通过策略管理服务（PMS）管理策略，由授权决策服务（ADS）给出决策，并提供 spctl 命令行和六种语言的 SDK。

Go · PMS + ADS · spctl CLI

Speedle Cloud 即将上线

适合想要托管授权 API、不想自己运维授权服务的开发者。

同一套策略模型和 SPDL，由 Speedle Cloud 托管：控制台管理服务、策略和令牌，Playground 验证策略，IsAllowed API 给出授权决策。目前提供基于示例数据的在线演示；登录即将开放，带令牌鉴权的 API 调用也在逐步上线。

免费公测 · 1 个服务 · 200 条策略 · 每日 10,000 次调用

Speedle AI

适合用 AI 管理权限的团队，也适合需要约束 AI 能访问什么的团队。

用 AI 管权限：开源策略建模 Agent Skill 把员工手册和法规转成可测试的 SPDL 模型。管住 AI 的权限：用 SPDL 模式覆盖数据与训练、模型发布、权限感知的 RAG、智能体、MCP 工具调用、智能体间调用（A2A）和零常驻权限（ZSP）。

MCP 服务器为发布预览；AI 模式是运行在 Speedle 引擎上的解决方案模式。

如何配合

同一套策略，从第一个服务到第一个智能体

三个产品由同一套引擎、一种策略语言和一套请求模型连接起来。Speedle Cloud 与 Engine 的 SPDL 语义一致，同一份策略可以从自托管 Speedle 带到 Speedle Cloud。

01

一套引擎，一种策略语言

Speedle Engine 是开源实现；Speedle Cloud 运行同一套策略模型、SPDL 和决策语义；Speedle AI 把同一套引擎用到 AI 系统上。

02

自托管或托管，按需选择

用 Engine 在自己的基础设施上运行完整链路，或在免费公测中使用 Cloud 保存策略并回答 IsAllowed 请求。Cloud API 与 Speedle ADS 兼容。

03

在之上加入 AI

Speedle AI 增加 AI 辅助的策略建模和面向 AI 智能体的策略模式。它建立在引擎与 Cloud 之上，不替代它们。

policy.spdl 
# Speedle Cloud demo policies
grant role reader get /books
deny user bob delete /books
grant user alice reader on /books

SPDL 示例来自 Speedle Cloud 演示。Speedle Engine 与 Speedle Cloud 使用同一种策略语言。

接入

从应用代码到智能体

六种语言的 SDK 调用授权 API；Speedle MCP 服务器把授权检查与策略管理带给 MCP 客户端。

六种语言的 SDK

六种 SDK 都调用 POST /authz-check/v1/is-allowed。Python、Java、Go、C#/.NET 和 Rust 已发布 0.2.0；Node.js 包尚未发布。六种 SDK 均支持自托管 Speedle；Speedle Cloud 支持即将推出。

  • Java
  • Python
  • Go
  • C#/.NET
  • Rust
  • Node.js

Speedle MCP

本地 stdio MCP 服务器，处于发布预览阶段，提供两种相互独立的模式：check 负责授权检查，manage 负责策略管理。目前尚未发布到 npm。
